# Regression catalog

Every defect found from M1 onward, what caused it, how it was fixed, and what now guards
it. A defect is only "closed" when an automated test (or, where automation is not
possible, a named tool) fails if it comes back. Test names refer to `tests/`.

| ID | Found | Symptom | Root cause | Fix | Guarded by |
|---|---|---|---|---|---|
| R1 | M1 | Process crash (access violation) when reading tracks | python-vlc's `Media.tracks_get()` struct layout is wrong for libVLC 3.0.24 x64 | Own ctypes definitions of the track structs | `test_tracks_are_listed`, `test_corpus_file_plays_with_correct_media_info` |
| R2 | M1 | Hardware decoder never detected | python-vlc `libvlc_log_get_context` needs out-params; the `TypeError` was swallowed in the log callback | Context lookup removed | `test_decoder_is_reported_once_decoding` |
| R3 | M1 | `play()` after `stop()` did nothing | READY → PLAYING is not a valid transition | `EngineBase.play()` reloads the selected media | `test_stop_returns_to_ready_and_play_restarts` (unit), `test_stop_then_play_restarts` (integration) |
| R4 | M1 | Rare crash or hang on close | A deferred engine call could run against a released handle | `EngineBase.close()` drains the worker before adapter teardown | `test_close_in_every_state_is_prompt` (8 states), `test_close_after_error_still_cleans_up` |
| R5 | M1 | Corrupt file shown as "ended" | libVLC reports unreadable files as Playing → EndReached, no error event | "Ended with nothing decoded" → `MEDIA_OPEN_FAILED` | `test_invalid_media_fails_without_playing_and_engine_recovers` |
| R6 | M1 | App froze on window close | Destroying the host window under a live libVLC video output deadlocks on the GIL (S2) | Close the engine before its window; detach the log callback first | `test_close_shuts_engine_down_before_window`, integration fixtures, `test_shutdown.py` |
| R7 | M1 | Access violation in processes that create several mpv instances | Not isolated (S1) | **Open** — mpv is the alternate engine; its tests are opt-in | `BABARIFY_TEST_MPV=1 pytest -k mpv` |
| R8 | M2 | Bad file briefly showed PLAYING | libVLC fires *Playing* before it knows the file is readable | Hold LOADING until confirmed by length, position or video output | `test_invalid_media_fails_without_playing_and_engine_recovers` (asserts no PLAYING) |
| R9 | M2 | Play/seek after end did nothing | An ended libVLC 3 player ignores `play()` | Restart with `stop()` + `play()`; seek-after-end pauses at target | `test_end_then_play_restarts`, `test_seek_after_end_pauses_at_target` |
| R10 | M2 | No codec/size for TS, PS and Ogg | Streams and video size arrive after *Playing* | Refresh media info on stream/vout events; retry while size unknown | Corpus test on `c_h264_ac3_720p.ts`, `c_mpeg2_mp2_576p.mpg`, `c_theora_vorbis_480p.ogv`, `e_interlaced_mpeg2_1080i.ts` |
| R11 | M2 | Raw fourccs (`mp4v`, `VP80`, …) | No mapping | Map to FFmpeg names | Corpus test (codec equality for 30+ files) |
| R12 | M2 | Position stuck after seeking while paused | libVLC sends no TimeChanged while paused | Report the accepted target | `test_controls_play_pause_seek_volume_rate` |
| R13 | M2 | Double-click on video ignored | libVLC's video window captured mouse/keys | `video_set_mouse_input(False)`, `video_set_key_input(False)` | `tools/real_input_check.py` (sends real input; run manually) |
| R14 | M2 | "4 Could not open…" in error text | libVLC log level prefix kept | Prefix stripped | `test_invalid_media_fails_without_playing_and_engine_recovers` |
| R15 | M2 | Error page overwritten by file title | Synchronous failure inside `open()` | Window updated before opening | `test_open_failure_shows_error_page` |
| R16 | M2 | Evidence screenshot captured another app | Screen grab of a covered window | Stay-on-top + ownership check before saving | `tools/player_screenshot.py` refuses to save (process control, not a test) |
| R17 | M3 | Status showed "decoder: none reported" while hardware decoding | Decoder logged after *Playing* | Status refreshed each second while playing | Screenshot evidence; `test_decoder_is_reported_once_decoding` covers the data source |
| R18 | M4 | Hardware decoding "Off" still used the GPU | libVLC 3.0.24 ignores `--avcodec-hw` at instance level | Per-media `:avcodec-hw=` option | `test_hardware_decoding_off_reports_software`; `tools/engine-benchmark/hw_decode_check.py` |
| R19 | M3 | Large window resize blocks the UI ~100–125 ms at 4K / 250 % | Qt layout + paint of the whole widget tree at high DPI; no single dominant part (M4 breakdown) | **Open** — see M4 report §4 | `tools/ui_responsiveness.py`, `tools/resize_probe.py` |
| R20 | M2/M4 | Handles and memory grew per engine; after ~100 engines in one process `libvlc_new` crashed (access violation) | Every libVLC 3.0.24 instance create/release leaks ~15 handles and ~0.5 MB (reproduced with bare libVLC, no Babarify code) | One shared libVLC instance per process; engines own only player and media | `test_repeated_engine_create_close` (run with `BABARIFY_ENGINE_CYCLES=50`), full default suite (~150 engines per process) |
| R22 | M5 | "Internal C++ object already deleted" in the test run | Playback info "Copy" reset its label 1.5 s later through a timer not tied to the dialog | Timer uses the button as context object, so Qt cancels it with the dialog | Full UI suite (failed intermittently before the fix) |
| R23 | M5 | Selected subtitle track or new subtitle delay showed nothing until much later | libVLC had already demuxed the next lines with the old settings | Re-seek to the current time after selecting a track or changing the delay | `test_subtitle_track_select_and_off`, `test_delays_are_applied_and_reset`; M5 spike screen measurements |
| R24 | M5 | Broken subtitle file "loaded" without any track | libVLC `add_slave` returns success before reading the file | Wait up to 2.5 s for a new subtitle track; otherwise a `Notice` | `test_unreadable_subtitle_gives_notice_and_playback_continues` (`s_broken.srt`, `s_empty.srt`) |
| R25 | M6 | Damaged library database crashed start-up instead of being replaced | The failed connection kept the file open, so Windows refused to move it aside, and the fresh database was then opened over the damaged file | Close the connection before moving the file; if it still cannot be moved, use an in-memory library and never overwrite the damaged file | `test_garbage_file_is_moved_aside_and_replaced`, `test_database_with_damaged_pages_is_recovered`, `test_damaged_database_is_reported_at_start` |
| R26 | M6 | Thumbnails grey and only a quarter wide | python-vlc declares the format callback's `chroma` as a read-only string, so the requested RV32 never reached libVLC | Callback declared with a writable pointer | `test_probe_reads_corpus_file` (buffer size = width × height × 4), M6 spike images |
| R27 | M6 | "NULL pointer access" reading tracks of a parsed file | python-vlc `tracks_get` dereferences empty union members | Shared `read_media_tracks` reads the libVLC 3 structs directly | `test_probe_reads_corpus_file` (45 corpus files) |
| R28 | M6 | Thumbnails silently not saved | `QImage.save` rejects a bytes format at runtime although the type stubs ask for bytes | Format taken from the `.jpg` suffix | `test_scan_then_metadata_and_thumbnails` (file exists and is non-empty) |
| R29 | M6 | Library status "damaged database" never visible | Shown before the engine's own status line replaced it | Shown once the engine is ready | `test_damaged_database_is_reported_at_start` |
| R30 | M7 | Picture adjustments showed wrong colours (hardware decoding) or no change (software decoding) after the first change | libVLC 3 applies adjust values changed while the filter is on unreliably | Adapter always switches the filter off, sets all values, switches it on again | `test_picture_adjustments_change_the_picture` (screen pixels, both decoders, successive changes) |
| R31 | M7 | Dialogs (Sync and delay, Library folders, Picture & Sound) drawn with a light default background and nearly invisible text | The theme never styled `QDialog` | Dialogs use the page background | Evidence screenshots `panel_*.png` (inspected) |
| R32 | M7 | Re-saving a profile under an existing name could lose it when the list was full | The replaced profile kept its old place, so trimming to 20 dropped the newest | A re-saved profile counts as the newest | `test_preferences_keep_picture_eq_and_profiles` |
| R33 | M7 | Full test run occasionally ended in an access violation (0xC0000005) within seconds, before any test ran (3 of 20 soak runs) | Collecting the engine tests probed mpv, which starts and ends a live mpv handle even when mpv tests are off; mpv's event thread then sometimes crashed (the "handled" 0xe24c4a02 seen since M5 came from the same probe) | mpv is probed only when `BABARIFY_TEST_MPV=1`; otherwise its tests are skipped without loading mpv | `tools/soak.ps1` (20 runs with fault logging); collection leaves `mpv` unimported |
| R34 | M8 | A web server could make the player open a local file: an HTTP redirect to `file:///…` played it (spike, plain libVLC); HLS manifests can name `file:` segments the same way | libVLC 3 follows redirects to any scheme it has a plugin for and has no option against it | libVLC never fetches web addresses: a loopback proxy fetches them, follows only http/https redirects and rewrites playlists; `--no-lua` | `test_redirect_to_a_local_file_is_refused` (proxy and real libVLC), `test_hls_with_a_local_file_segment_is_refused`, `test_playlist_skips_local_and_vlc_entries` |
| R35 | M8 | A remote M3U playlist with a valid web entry failed to play | The proxy labelled every rewritten playlist as HLS, so libVLC treated a plain list as a broken stream | Plain M3U is served as `audio/x-mpegurl`; HLS (with `#EXT-X-` tags) as HLS | `test_plain_m3u_is_not_labelled_hls`, `test_playlist_skips_local_and_vlc_entries` |
| R36 | M8 | Seek-bar preview sometimes never appeared for the first hover | A hover between "file opened" on the worker and its notice on the UI thread was dropped | Requests queue as soon as a file is set; the worker skips them if opening failed | `test_hovering_the_seek_bar_shows_time_chapter_and_picture` |
| R37 | M8 | A long bookmark name kept a trailing space | Cut to 120 characters after collapsing spaces, without stripping | Strip after cutting | `test_bookmarks_are_kept_per_file_in_time_order` |
| R38 | M8 | Media information drawn on a white background with nearly invisible text | The theme never styled `QTextBrowser` (same class as R31) | Text views use the panel background and text colour | Evidence `media_info.png` (inspected before and after) |
| R39 | M8 | The last line of a long error reason was cut off on the player page | A word-wrapped label centred in its box was laid out too narrow and too short | The message body is at least 480 px wide | Evidence `redirect_refused.png` (inspected before and after) |
| R40 | M9 | Subtitles generated with "Detect automatically" were named `.und.` instead of the detected language | The file name was chosen before the worker knew the language | The job renames the file once the language is reported; a regenerated file replaces the old one on disk | `test_generating_subtitles_adds_a_machine_track_and_indexes_it` |
| R41 | M9 | The transcription worker ran at normal priority, competing with playback | `SetPriorityClass` was called without argument types: on 64-bit Windows the process pseudo-handle was passed as a 32-bit int and the call failed silently | Argument and return types declared; failure reported as a warning | `test_worker_turns_speech_into_timed_subtitles` (checks the worker process's priority class) |
